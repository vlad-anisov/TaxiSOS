**Это ключ к решению!**

|------------|----------------|

Это позволяет **отличить** Bluetooth-кнопку от физических кнопок!

## 🔧 Техническая реализация

### Новый подход: AccessibilityService + TYPE_WINDOW_STATE_CHANGED

#### Как работает:

```
1. AccessibilityService отслеживает события окон
   ↓
2. Приходит событие TYPE_WINDOW_STATE_CHANGED (32) - открытие окна
   ↓
3. Проверяем: это окно громкости?
   ↓
4. Проверяем: изменилась ли громкость?
   ├─ НЕТ → Это Bluetooth-кнопка! ✓ ЗАПУСКАЕМ ДЕЙСТВИЕ
   └─ ДА → Это физическая кнопка, игнорируем
```

#### Код (VolumeButtonAccessibilityService.kt):

```kotlin
override fun onAccessibilityEvent(event: AccessibilityEvent?) {
    if (event?.eventType == AccessibilityEvent.TYPE_WINDOW_STATE_CHANGED) {
        
        // Это окно громкости?
        val isVolumeDialog = packageName.contains("android") || 
                             className.contains("Volume")
        
        if (isVolumeDialog) {
            val currentVolume = audioManager.getStreamVolume(AudioManager.STREAM_MUSIC)
            
            // Ключевой момент: громкость изменилась?
            if (currentVolume == lastKnownVolume) {
                // Громкость НЕ изменилась → Bluetooth-кнопка!
                Log.d(TAG, "🎯 Bluetooth-кнопка обнаружена!")
                handleButtonPress() // Запускаем действие
            } else {
                // Громкость изменилась → физическая кнопка
                Log.d(TAG, "→ Физическая кнопка, игнорируем")
                lastKnownVolume = currentVolume
            }
        }
    }
}
```

## ⚙️ Технические детали

### Почему AccessibilityService?

1. **Получает TYPE_WINDOW_STATE_CHANGED** - событие открытия окна громкости
2. **Может проверять уровень громкости** через AudioManager
3. **Работает в фоне** даже когда приложение закрыто
4. **Официально поддерживается** Android

### Почему НЕ VolumeKeyListener?

- ❌ `VOLUME_CHANGED_ACTION` срабатывает **только** когда громкость **действительно меняется**
- ❌ Первое нажатие Bluetooth-кнопки **НЕ меняет громкость** → событие не приходит
- ❌ Невозможно отличить источник изменения громкости

### Почему это работает?

Bluetooth-кнопка на первом нажатии:
1. Посылает сигнал системе "показать окно громкости"
2. Окно открывается (TYPE_WINDOW_STATE_CHANGED)
3. Но громкость НЕ меняется (нужно нажать еще раз)

Физические кнопки:
1. Сразу меняют громкость
2. Окно открывается, громкость уже изменена
3. AccessibilityService видит: "громкость изменилась" → игнорирует

## 🎨 Изменения в коде

### 1. `VolumeButtonAccessibilityService.kt` - Полная переработка

**Было:**
- Пытались перехватывать `onKeyEvent()` (не работало)

**Стало:**
- Обрабатываем `onAccessibilityEvent()`
- Отслеживаем `TYPE_WINDOW_STATE_CHANGED` (32)
- Проверяем изменение громкости
- Не трогаем громкость вообще

### 2. `BluetoothButtonService.kt` - Упрощение

**Было:**
- Запускал `VolumeKeyListener`
- Сложная логика восстановления громкости

**Стало:**
- Только `MediaSession` для стандартных медиа-кнопок
- Вся логика Bluetooth-кнопки в `AccessibilityService`

### 3. Строковые ресурсы - Обновлены

**Что изменилось:**
- Указано, что нужно **ОДНО нажатие**
- Подчеркнута **обязательность** AccessibilityService
- Гарантия, что громкость **НЕ сбросится**
- Уверенность, что физические кнопки **работают нормально**
