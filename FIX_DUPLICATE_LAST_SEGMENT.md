# Исправление дублирования последнего видеосегмента

## Описание проблемы

При нажатии кнопки STOP до истечения времени сегмента, последний (неполный) видеосегмент отправлялся дважды в Telegram канал, но только один раз в "Избранное" (контактам).

### Сценарий проблемы

**Настройки:** 10 секунд на сегмент

**Действия пользователя:**
1. Запись 10 секунд → отправлен сегмент 1 ✅
2. Запись 10 секунд → отправлен сегмент 2 ✅
3. Запись 4 секунды → нажата кнопка STOP

**Результат ДО исправления:**
- В "Избранном": 2 видео по 10 сек ✅
- В канале: 2 видео по 10 сек + **2 ОДИНАКОВЫХ видео по 4 сек** ❌

**Ожидаемый результат:**
- В "Избранном": 2 видео по 10 сек + 1 видео 4 сек ✅
- В канале: 2 видео по 10 сек + **1 видео 4 сек** ✅

## Анализ причины

### Два пути отправки видео

1. **Цикл записи сегментов** (`startRecord()`)
   - Записывает сегмент заданной длительности
   - После завершения записи вызывает `sendVideo(file)`
   - Отправляет в канал через Bot API
   - Отправляет контактам через TDLib

2. **Финализация последнего сегмента** (`finalizeAndSendLastSegment()`)
   - Вызывается при нажатии STOP
   - Принудительно останавливает текущую запись
   - Отправляет последний (неполный) сегмент через `sendVideoNow(file)`
   - Также отправляет в канал и контактам

### Почему возникало дублирование

Когда пользователь нажимает STOP до истечения времени сегмента:

```
T=0s:    Начало записи сегмента 3
T=4s:    Пользователь нажимает STOP
         ↓
         1. finalizeAndSendLastSegment() останавливает запись
         2. Отправляет файл через sendVideoNow() → в канал и контактам
         ↓
         3. Цикл записи завершает обработку того же сегмента
         4. Отправляет файл через sendVideo() → В КАНАЛ ПОВТОРНО!
```

### Почему в "Избранное" попадало только один раз

TDLib имеет внутренние задержки и кэширование, что иногда предотвращало повторную отправку того же файла. Но это было ненадежно и зависело от таймингов.

## Решение

Добавлен флаг `isFinalizingLastSegment` для предотвращения двойной отправки последнего сегмента.

### Изменения в коде

**Файл:** `app/src/main/java/com/example/sostaxi/MainActivity.kt`

#### 1. Добавлена переменная флага

```kotlin
private var isSegmentRecordingActive: Boolean = false
private var isFinalizingLastSegment: Boolean = false  // НОВОЕ
```

#### 2. Флаг устанавливается при финализации

```kotlin
private suspend fun finalizeAndSendLastSegment() {
    // Устанавливаем флаг финализации, чтобы избежать двойной отправки
    isFinalizingLastSegment = true
    
    var lastFile = currentSegmentFile
    // ... остальной код ...
    
    if (lastFile == null) {
        isFinalizingLastSegment = false
        return
    }
    
    // ... отправка последнего сегмента ...
}
```

#### 3. Проверка флага перед отправкой в цикле

```kotlin
// В методе startRecord(), в цикле записи сегментов:

// Проверяем, что файл создался и имеет корректный размер
if (file.exists() && file.length() > 1000) {
    // НОВАЯ ПРОВЕРКА: не началась ли финализация последнего сегмента
    if (isFinalizingLastSegment) {
        Log.d("MainActivity", "Пропускаем отправку сегмента $segmentCount - идет финализация последнего сегмента")
    } else {
        // Сканируем файл и отправляем
        MediaScannerConnection.scanFile(this@MainActivity, arrayOf(file.absolutePath), null, null)
        
        // Копируем в галерею, если настройка включена
        val shouldSaveToGallery = getSharedPreferences(PREFS_TAXI, Context.MODE_PRIVATE)
            .getBoolean(KEY_SAVE_SEGMENTS_TO_GALLERY, false)
        if (shouldSaveToGallery) {
            copyVideoToGallery(file)
        }
        
        sendVideo(file)
        Log.d("MainActivity", "Сегмент $segmentCount отправлен")
    }
}
```

#### 4. Сброс флага при старте и остановке

```kotlin
private fun start() {
    if (isActive) return
    
    Log.d("MainActivity", "Начинаем запуск с режимом $currentWorkMode")
    
    // Сбрасываем флаг финализации последнего сегмента при новом старте
    isFinalizingLastSegment = false
    
    // ... остальной код ...
}

private fun stop() {
    // ... код остановки ...
    
    // Сбрасываем флаги инициализации камер
    isStreamingCameraPrepared = false
    isRecordingCameraPrepared = false
    
    // Сбрасываем флаг финализации последнего сегмента
    isFinalizingLastSegment = false
}
```

## Логика работы после исправления

```
T=0s:    Начало записи сегмента 3
         isFinalizingLastSegment = false

T=4s:    Пользователь нажимает STOP
         ↓
         1. isFinalizingLastSegment = true (УСТАНОВЛЕН ФЛАГ)
         2. finalizeAndSendLastSegment() останавливает запись
         3. Отправляет файл через sendVideoNow() → в канал и контактам
         ↓
         4. Цикл записи завершает обработку сегмента
         5. ПРОВЕРКА: if (isFinalizingLastSegment) → true
         6. Отправка ПРОПУЩЕНА ✅
         7. Лог: "Пропускаем отправку - идет финализация"

T=5s:    Остановка завершена
         isFinalizingLastSegment = false (СБРОШЕН)
```

## Преимущества решения

1. **✅ Простота** - добавлен всего один boolean флаг
2. **✅ Надежность** - работает независимо от таймингов и задержек
3. **✅ Эффективность** - минимальные изменения кода
4. **✅ Совместимость** - не влияет на другие части приложения
5. **✅ Безопасность** - флаг всегда сбрасывается в правильных местах

## Тестирование

Для проверки исправления:

1. Настройте длительность сегмента на 10 секунд
2. Выберите "Избранное" и любой канал для отправки
3. Запустите запись (START)
4. Подождите более 10 секунд (чтобы записались 2 полных сегмента)
5. Нажмите STOP до истечения 10 секунд третьего сегмента
6. Проверьте:
   - В канале должно быть ровно 3 видео (2 по 10 сек + 1 неполное)
   - В "Избранном" должно быть ровно 3 видео (2 по 10 сек + 1 неполное)
   - **НЕ должно быть дубликатов последнего сегмента**
