# Автоматическое закрытие приложения после остановки

## Проблема

После остановки трансляции или записи видео сегментов приложение оставалось открытым (хотя и полностью прозрачным). Пользователю приходилось вручную выходить из приложения.

## Решение

Добавлено автоматическое закрытие приложения после остановки трансляции/записи с использованием:
- `finishAffinity()` - закрывает все активности в стеке задач
- `finishAndRemoveTask()` - полностью удаляет задачу из системы
- ~~Задержка 2 секунды для гарантированной отправки последнего видео сегмента~~ **Обновлено:** Задержка уменьшена до 500мс

> **Важное обновление (20.10.2025):** Задержка закрытия уменьшена с 2000мс до 500мс для более быстрого отклика приложения. Также добавлено исправление для закрытия из режима PiP (см. `PIP_CLOSE_FIX.md`).

## Изменения

### 1. Улучшена обработка закрытия через плитку/Bluetooth (строки 2707-2741)

```kotlin
quickTileAction == "stop_and_close" -> {
    Log.d("MainActivity", "Получен сигнал закрытия через плитку")
    isClosingFromTile = true

    // Останавливаем приложение
    if (isActive) {
        Log.d("MainActivity", "Останавливаем активность")
        stop()
    }
    
    // Сбрасываем состояние плиток
    try {
        StreamingTileService.setTileState(this, false)
        VideoSegmentsTileService.setTileState(this, false)
    } catch (_: Exception) {}
    
    // Закрываем приложение с задержкой для завершения отправки сегментов
    android.os.Handler(android.os.Looper.getMainLooper()).postDelayed({
        try {
            Log.d("MainActivity", "Закрываем приложение полностью")
            // Используем finishAffinity() для закрытия всех активностей
            finishAffinity()
            // Для полного выхода из приложения
            finishAndRemoveTask()
        } catch (e: Exception) {
            Log.e("MainActivity", "Ошибка при закрытии приложения: ${e.message}")
            // Запасной вариант - просто finish()
            try { finish() } catch (_: Exception) {}
        } finally {
            // Сбрасываем флаг на случай, если приложение не закроется
            isClosingFromTile = false
        }
    }, 500) // Минимальная задержка 500мс
}
```

### 2. Добавлено автозакрытие в методе `stop()` (строки 1318-1334)

```kotlin
// Автоматически закрываем приложение после остановки
// Задержка нужна для завершения отправки последнего сегмента
if (isClosingFromTile) {
    // Если закрытие инициировано через плитку/Bluetooth, обработка уже в handleQuickTileIntent()
    Log.d("MainActivity", "Закрытие будет обработано в handleQuickTileIntent()")
} else {
    // Обычная остановка - закрываем приложение с задержкой
    android.os.Handler(android.os.Looper.getMainLooper()).postDelayed({
        try {
            Log.d("MainActivity", "Автоматическое закрытие приложения после остановки")
            finishAffinity()
        } catch (e: Exception) {
            Log.e("MainActivity", "Ошибка при автозакрытии: ${e.message}")
            try { finish() } catch (_: Exception) {}
        }
    }, 500) // Минимальная задержка 500мс
}
```

## Как это работает

### Остановка через Bluetooth-кнопку или плитку Quick Settings:

1. `VolumeButtonAccessibilityService` или `TileService` отправляет Intent с `quick_tile_action = "stop_and_close"`
2. `MainActivity` получает Intent в `handleQuickTileIntent()`
3. Вызывается `stop()` для остановки камеры и отправки последнего сегмента
4. Через 500мс вызываются:
   - `finishAffinity()` - закрывает все Activity
   - `finishAndRemoveTask()` - удаляет задачу из системы

### Остановка другими способами (кнопка в UI, автостоп по таймеру):

1. Вызывается `stop()`
2. Если `isClosingFromTile = false`, то через 500мс вызывается `finishAffinity()`
3. Приложение полностью закрывается

## Важные детали

### Задержка 500мс

~~Задержка в 2 секунды~~ **Обновлено: теперь 500мс**

Минимальная задержка необходима для:
- ✅ Завершения вызова метода `stop()`
- ✅ Корректного освобождения ресурсов камеры
- ✅ Финализации текущего процесса остановки
- ⚠️ Отправка последнего сегмента происходит асинхронно и не зависит от задержки

### Методы закрытия

1. **`finishAffinity()`**
   - Закрывает все активности в текущей задаче
   - Рекомендуется официальной документацией Android
   - Корректно завершает жизненный цикл приложения

2. **`finishAndRemoveTask()`**
   - Дополнительно удаляет задачу из списка недавних приложений
   - Полностью очищает приложение из памяти системы

3. **Запасной `finish()`**
   - Используется в catch-блоке на случай ошибок
   - Закрывает текущую Activity

### НЕ используется

❌ **`System.exit(0)`** - не рекомендуется Android, может привести к:
- Некорректному завершению жизненного цикла
- Незакрытым ресурсам
- Проблемам с системой

❌ **`android.os.Process.killProcess()`** - то же самое, убивает процесс без очистки
